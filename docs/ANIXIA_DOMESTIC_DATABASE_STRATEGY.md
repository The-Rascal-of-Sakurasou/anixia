# ANIXIA 国内最大級アニメ総合データベース化計画

更新日：2026-11-24

## 目標

ANIXIAを、日本のアニメ作品を歴史的作品から最新作まで横断して調べられる、国内最大級の総合データベースへ育てる。作品数だけでなく、各話・人物・キャスト・スタッフ・制作会社・シリーズ・放送情報・配信情報・原作・主題歌の正確性と網羅性を同時に高める。

### 数値目標（段階目標）

| 指標 | 第1段階 | 第2段階 | 長期目標 |
|---|---:|---:|---:|
| 作品 | 10,000件 | 15,000件以上 | 収録方針内の作品を継続調査 |
| エピソード | 50,000件 | 175,000件以上 | 作品の実際の話数に近づける |
| ポスター | 公開作品の80% | 95% | 権利確認済み画像で可能な限り網羅 |
| 人物・キャスト | 主要人物から拡充 | 主要キャストの高い網羅性 | 出典確認可能な範囲で継続拡充 |
| スタッフ・制作会社 | 主要クレジット | 作品ごとの主要スタッフ | 役職別の網羅性を向上 |
| 作品間関係 | 主要シリーズ | 続編・前日譚・スピンオフ | 公式根拠に基づき網羅 |

参考ベンチマークとして、日本動画協会の「アニメ大全」は2022年7月末時点で作品14,710件、エピソード175,755件を公表した。これは2022年時点の歴史的基準であり、現在の他サービスの登録数を示すものではない。ANIXIAはこの基準を超えることを中期目標とする。

## 収録対象

- 日本で制作・公開されたアニメーション作品を中心に、1910年代から現在までを対象とする。
- TVシリーズ、劇場作品、短編、OVA、ONA、TVスペシャル、独立した映像作品を区別して登録する。
- 日本国外の作品でも、日本語タイトルがあり、ANIXIAの収録方針に適合する場合は登録候補にできる。
- 同じ作品の再放送・再編集・リマスターを新規作品として重複登録しない。
- リメイク、別シリーズ、続編、スピンオフは、作品として独立している場合に別レコードとし、シリーズ・作品間関係で結ぶ。
- 予告編、CM、PV、販促映像、単なる告知、作品単位でない放送枠・企画は原則として収録しない。
- 成人向け・不適切コンテンツは既定の審査基準に従い、一般公開対象を個別に判断する。
- 判断が曖昧な候補は削除せず非公開の審査キューに残し、理由と出典を記録する。

## データモデル

作品本体を中心に、次の情報を独立した関連データとして管理する。

1. 作品：正式タイトル、読み、別名、英題、ローマ字、形式、公開年、開始日、終了日、上映時間、話数、国、公式サイト、あらすじの出典。
2. エピソード：話数、話順、サブタイトル、放送日、時間、種別、出典、公開審査状態。
3. シリーズ・作品間関係：シリーズ、前作、続編、スピンオフ、リメイク、総集編、関連作品。
4. 人物・キャラクター：人物名、読み、別名、キャラクター名、登場作品。
5. キャスト：声優、配役、言語、役割、クレジット出典。
6. スタッフ：監督、シリーズ構成、脚本、キャラクターデザイン、音楽、美術、撮影、編集などの役職別クレジット。
7. 制作組織：アニメーション制作、制作協力、製作委員会、配給、放送局を混同せずに管理。
8. ジャンル・タグ：少数の安定したジャンルと、必要な場合だけの補助タグを分ける。
9. 放送情報：放送局、放送曜日、開始時刻、期間、地域、放送形態。
10. 配信情報：配信サービス、地域、見放題・無料・レンタル・購入、配信期間。
11. 原作情報：漫画、小説、ライトノベル、Web小説、ゲーム、ビジュアルノベル、オリジナル等の媒体、著者、出版社。
12. 主題歌：OP、ED、挿入歌、曲名、アーティスト、クレジット。
13. 画像・権利情報：画像URL、出典、ライセンス、作者表記、利用条件、最終確認日時。
14. 外部識別子：Wikidata、Annict等の提供元別ID。作品の同一性を確認してから紐付ける。
15. データ監査：取得元、取得日時、確認日時、確認者、訂正履歴、公開判定理由。

## データソース・権利方針

- Wikidata：CC0の構造化データを作品名・日付・識別子・関係等に利用。過負荷を避けて段階取得する。
- しょぼいカレンダー：利用条件で認められたタイトル・読み・略称等の構造化データに限定する。API応答コードと形式を検証する。
- Annict：2026-11-25施行予定の規約を施行後に再確認し、権利審査が承認されるまで無効のままにする。利用可能になった場合もアプリ内表示に必要な範囲で使い、データセットとして再配布しない。
- AniList：ANIXIA運営者が申告した許諾の範囲内で画像照合・表示に限定。AniList由来の作品メタデータの一括収集には使わない。
- Wikimedia Commons：ファイル単位でライセンス、ライセンスURL、作者・クレジットを検証できる画像だけを採用する。
- 公式サイト・放送局・制作会社・権利者：作品の公開日、話数、スタッフ・キャスト、制作情報の一次確認に優先する。
- TMDB、Jikan、その他のサービス：規約、商用条件、再配布、画像権利、費用、API安定性を審査するまで本番データソースにしない。
- Webページ本文や画像を無断で一括コピーしない。著作権のあるあらすじ本文・歌詞・音源は収録しない。
- 各データ項目に出典を持たせ、出典不明の値を確定情報として登録しない。

## 品質基準

- タイトルの正規化・別名照合・外部ID照合を組み合わせて重複を防ぐ。
- 外部IDの一意制約だけでなく、タイトル・公開年・形式・シリーズを用いて衝突候補を検出する。
- 作品の話数と、個別エピソードの登録数を別指標として扱う。
- 話数不明・未確定・変動中の作品に推測値を入れない。
- 続編・前日譚・制作会社・声優・スタッフの関係を、根拠なく推測して登録しない。
- 作品画像は作品との一致と利用条件を確認し、画像未確認の作品を画像ありとして扱わない。
- 新規候補は原則非公開で取り込み、公開条件を満たすものだけを公開する。
- 非公開理由を「日本語タイトル不足」「形式不明」「重複疑い」「対象外」「権利確認待ち」「情報矛盾」等に分類し、理由が解消したら再審査する。
- 定期的に欠損率、出典率、重複候補、画像率、話数一致率、更新遅延を集計する。

## 検索・発見機能

- 日本語タイトル・読み仮名・別名・英題・ローマ字を対象にした日本語向け検索。
- 年代、年、季節、作品形式、制作会社、監督、声優、スタッフ、原作媒体、ジャンルでの絞り込み。
- 五十音インデックス、年代別一覧、放送クール別一覧、制作会社別一覧、人物別一覧。
- 放送日・放送局・話数から探すカレンダー。
- 同じ時期に放送された作品、共通キャスト、同一シリーズの作品をたどる導線。
- 検索候補は別名を含め、検索結果では正式タイトルと該当した別名を区別する。
- 検索ランキングや人気度は外部APIから取り込まない。ANIXIA内部の利用データと外部メタデータを混同しない。

## 稼働中の自動処理（2026-11-24時点）

- Wikidata作品候補同期：毎分実行の一時的な拡張バッチ。10,000作品到達または設定された停止時刻で停止する条件付き。
- Wikidata追加情報同期：5分ごとの一時的な拡張バッチ。
- 季節作品同期：日次実行。
- しょぼいカレンダーのタイトル補完：権利承認済みの構造化タイトル情報を使用。
- ポスター同期：画像利用条件を確認する処理を継続。
- Wikidataエピソード同期：10分ごと、1回30作品を順次処理。新規エピソードは非公開で保存し、管理者審査後に公開。
- 取得元の規約・レート制限・API障害に従い、同期を一時停止できるようにする。

## 開発フェーズ

### Phase 1：カタログ基盤
- 10,000作品を中間目標に、歴史的作品・映画・OVA・ONA・TVシリーズを拡充。
- タイトル・形式・年・外部ID・画像の品質監査を行う。
- 重複・対象外・日本語タイトル欠損の審査キューを整える。

### Phase 2：エピソード・シリーズ
- 話数情報と各話タイトルを照合。
- 放送日・話順・特別編・総集編・欠番を扱う。
- 続編・前日譚・リメイク・スピンオフを公式根拠で関連付ける。

### Phase 3：人物・制作情報
- 声優・キャラクター・スタッフ・制作会社のカバレッジを高める。
- 役職と制作組織の種類を正規化。
- 同姓同名・改名・別名を人物IDで統合。

### Phase 4：放送・配信・原作・音楽
- 放送局・曜日・時間・期間、地域別配信状況を登録。
- 原作媒体・著者・出版社・レーベルを関連付け。
- OP・ED・挿入歌の曲名・アーティスト・担当話数を登録。

### Phase 5：国内最大級の網羅性・継続運用
- 15,000作品・175,000エピソードを超えることを中期的な歴史ベンチマークにする。
- 収録範囲を継続調査し、最新の公開ベンチマークと比較する。
- 更新監視、品質レポート、管理者審査、ユーザーからの修正申請を整備する。
- 登録数だけでなく、出典付き情報の比率と正確性を公開する。

## 変更管理

- 本番DBの変更は追加的なマイグレーションを優先し、既存データを不用意に削除しない。
- 大量更新の前に件数・重複・公開状態を確認する。
- 新規インポーターは小規模テスト、重複検査、RLS確認後に定期実行へ移す。
- 秘密情報はSupabase Vault/Secretsに置き、GitHubやブラウザーへ出さない。
- ブラウザー実機確認をしていないUIは完成扱いにしない。
- 無料枠・実行時間・APIレート制限を監視し、想定外の課金を避ける。


## 追加の欠損監査（2026-11-24）

公開作品3,983件の集計では、日本語タイトル・公開年は全件設定済みだが、読み仮名975件、作品単位の話数2,749件、公式URL736件、ポスターURL2,133件、あらすじ0件だった。読み仮名・公式URL・話数の未設定を優先して補完する。あらすじは無断転載を行わず、利用条件が確認できるデータか、ANIXIA独自の編集方針で作成した説明に限る。

しょぼいカレンダー同期の旧実装には公開作品の取得上限2,000件があった。ページング方式に変更し、最大20,000件まで照合対象に含める修正をEdge Function version 3としてデプロイした。次回同期で実際の補完件数と曖昧一致の件数を確認する。
