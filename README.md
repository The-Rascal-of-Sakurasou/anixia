# ANIXIA

**ANIXIA** は、日本語で使いやすいアニメ総合プラットフォームです。

作品データベースを中心に、検索・おすすめ診断・クイズ・ランキング・視聴管理・レビュー・ユーザー機能を一体化し、作品データベースを中心に、情報を探しやすく整理したサービスを目指します。

## UI / デザイン方針

- 対応言語：日本語・英語
- 日本語を主軸に、英語へ切り替え可能なインターフェース
- MyAnimeListを情報設計の参考にしつつ、画面表現はANIXIA独自に設計
- キャッチコピーを設けず、検索・作品情報・ランキングなどの機能を中心に構成
- PC・タブレット・スマートフォンに対応

## 参考サイト・参考プロジェクト

ANIXIAの設計では、以下を参考にします。参考サイトはUI・情報設計・機能設計のベンチマークであり、作品データを取得するAPIとは区別します。

| サイト | 参考にする領域 |
|---|---|
| [日本のアニメ大全](https://animedb.jp/) | 国内作品の網羅性・歴史的作品の収録 |
| [MyAnimeList](https://myanimelist.net/) | 大規模作品DB・作品詳細・ユーザー評価やリスト機能 |
| [きせつあにめ](https://kisetsu-anime.com/) | 作品情報・放送期別の整理 |
| [Animecia](https://media-mania.github.io/Animecia/index.html) | 日本語中心のアニメDB、作品情報・検索・発見体験 |
| [Anime Quiz World（AQW）](https://the-rascal-of-sakurasou.github.io/anime-quiz-world/index.html) | アニメクイズ・おすすめ診断・作品検索・ユーザー参加型機能 |

参考サイトの情報やデザインをそのまま複製せず、ANIXIA独自の情報設計と権利方針に沿って取り入れます。Wikidata等のデータ取得元は [データソース方針](docs/DATA_SOURCES.md) で別途管理します。

## UX・品質改善方針

ANIXIAでは、次の改善を優先します。

- **モバイル操作**：スマートフォン向けにナビゲーションを整理し、ハンバーガーメニュー等で主要導線を分かりやすくする。
- **重複導線の削減**：ヘッダーとトップページの機能リンクを整理し、主要機能を見つけやすくする。
- **開発中機能の明示**：未実装・デモ機能には状態表示と案内を設け、完成機能と誤認させない。
- **出典・権利情報**：データ出典ページと作品詳細で、確認できるデータソース・画像出典・利用条件を明記する。
- **検索強化**：放送時期・制作会社・声優等の複合絞り込みと、タイトル・別名の入力補完を整備する。
- **コミュニティ保護**：ネタバレの表示切替、通報、モデレーション機能を整える。
- **画像表示の高速化**：遅延読み込み、画像サイズ最適化、権利条件に適合するWebP等の活用を進める。
- **多言語の一貫性**：UIだけでなく作品データの日本語・英語表示と未翻訳時のフォールバックを統一する。

詳細な要件と優先順位は [国内最大級アニメ総合データベース化計画](docs/ANIXIA_DOMESTIC_DATABASE_STRATEGY.md)、[5サイトの参考ベンチマークとANIXIA独自仕様](docs/ANIXIA_REFERENCE_BENCHMARK.md)、[共通品質基準](docs/CROSS_SITE_QUALITY_STANDARD.md) を参照してください。

## 主な機能領域

- **アニメデータベース**：日本語タイトル、別名、英語名、ローマ字、あらすじ、形式、放送時期、話数、画像、ジャンル、制作会社、人物・キャラクター情報
- **検索・発見**：タイトル検索、五十音順、ジャンル・年代・クール・形式・制作会社などの絞り込み
- **作品詳細**：作品情報、関連作品、人物・キャラクター、評価、レビュー
- **視聴管理**：お気に入り、視聴予定、視聴中、視聴済み、中断、話数進捗
- **おすすめ診断**：AIを使わず、回答と条件・重み付けによって候補作品を提示
- **クイズ**：作品知識クイズ、難易度、回答履歴、スコア
- **ランキング・比較**：評価、人気、レビュー、シーズン別ランキング、複数作品比較
- **ユーザー機能**：アカウント、プロフィール、個人評価、レビュー、実績
- **管理機能**：作品・ジャンル・制作会社・クイズ・レビュー・おすすめ枠などの管理

## データソース方針

- 初期作品データ：Wikidataの構造化データ（CC0）。作品名・別名・日付・話数・識別子等に限定し、画像やあらすじ本文は取り込まない。
- しょぼいカレンダー：タイトルの一意な完全一致照合、読み仮名・略称・英題の補完に利用。画像やあらすじ本文は取り込まない。
- 追加候補：Annict API。2026-11-25施行予定の規約を確認後に利用可否を判断する。
- Jikan / TMDB：利用条件・再配布・商用利用条件の確認が完了するまで未採用。
- AniList：ANIXIA向け画像利用許可を得たとの運営者申告に基づき、ポスター画像の照合・表示に限定して採用。作品メタデータの一括収集・保存には利用しない。

データの出典・利用条件・登録状況は [データソース方針](docs/DATA_SOURCES.md) を参照してください。

## セキュリティ方針

- Supabase Authによるアカウント管理
- ユーザー固有データはRow Level Security（RLS）で本人に限定
- 管理者権限を一般ユーザーから分離
- クイズの正解データは公開APIから分離し、サーバー側で採点
- 公開クライアントにはpublishable keyのみを使用し、service role keyを含めない

## 開発原則

1. 旧サイトのデータを不用意に削除・変更しない。
2. 新ANIXIAのDBと画面を段階的に接続し、旧DBへの参照を残さない状態を目指す。
3. 既存機能を再実装する前に、テーブル・RLS・画面の実装状況を照合する。
4. 画面・データ・権限を一体でテストし、未検証機能を完成扱いにしない。
5. 外部API・画像・文章の利用条件を確認する。
6. 月額0円を目標とし、無料枠の上限と将来の費用発生条件を監視する。
